# Codex project instructions

## Session continuity

Project ID: `sail-lore`.

At the start of a task, read `PROJECT-STATUS.md` and the relevant sections of `README.md` and `LAUNCH.md`. Inspect the current branch and working tree before treating a saved checkpoint as current. Read only the additional material relevant to the task.

Keep a brief restart note in `PROJECT-STATUS.md` after meaningful progress, on a blocker, and at wrap-up. Record the outcome, unfinished work, one concrete next action, evidence, timestamp, and branch/revision when relevant. Distinguish working-branch changes from released behavior. Preserve unrelated notes and never invent a reason the user stopped.

The shared overview is the private Google Doc **Codex Projects — Where I Am & What’s Next** in the user's **Codex Shared** Drive folder. Its project entry is identified by `sail-lore`. When connected Google Drive is available:
- Read the current matching entry before updating it.
- Update only that project's summary; preserve other projects and the user's edits.
- Use revision-guarded edits when supported, and verify the changed section.
- Save the local checkpoint with `Overview sync: pending` before attempting the shared update, then mark it synced with the actual timestamp only after readback succeeds.

If Drive is unavailable, continue the task using the local note and leave the overview update pending. Reconcile pending updates against the current files and shared entry on the next connected session; surface conflicting claims rather than silently choosing one. Do not copy complete chat transcripts, secrets, credentials, or private source material into the overview.

These are checkpoints during active sessions, not a background synchronization service.
